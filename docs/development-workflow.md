# Development Workflow

> Development standards for the Francesca Digital project.

---

# Philosophy

Consistency is more valuable than speed.

Every contribution should improve the project.

---

# Git Workflow

```
Feature
    ↓
Commit
    ↓
Review
    ↓
Merge
```

---

# Commit Messages

Use conventional commit style.

Examples:

- feat:
- fix:
- docs:
- refactor:
- style:
- chore:
- perf:

---

# Code Style

Code should be:

- readable;
- predictable;
- maintainable;
- well-structured.

Readable code is preferred over clever code.

---

# Components

Each component should:

- solve one problem;
- have a clear API;
- avoid duplication;
- remain reusable.

---

# Documentation

Major architectural decisions should always be documented.

Documentation evolves together with the project.

---

# Quality Standards

Before merging, verify:

- readability;
- responsiveness;
- accessibility;
- performance;
- consistency.

---

# Principle

Build software that future developers — including yourself — will enjoy maintaining.
